# MD防误写机制使用说明

## 🛡️ 功能概述

MD防误写机制是一个智能的数据保护系统，通过识别用户操作意图来防止异常数据丢失，确保MD底座数据的安全性。

## 🎯 核心原理

### 操作来源识别
系统会标记每个删除操作的来源：

- ✅ **合法删除**：有明确用户操作标记
  - 键盘Delete键删除
  - UI按钮删除
  - 右键菜单删除
  - 程序API调用删除
  - 级联删除（父节点删除导致）

- ❌ **异常丢失**：无用户操作标记
  - JavaScript错误导致节点丢失
  - 渲染异常导致数据重置
  - 网络同步冲突覆盖
  - 浏览器崩溃恢复异常

### 安全策略
```
写入前验证 → 检查删除操作合法性 → 决定是否写入MD底座

合法删除 → 正常写入MD底座
异常丢失 → 阻止写入，保存到隔离区域，通知用户
```

## 🚀 使用方法

### 1. 自动保护（无需操作）
- 系统自动运行，用户正常使用脑图即可
- 所有合法的删除操作都会正常同步到MD底座
- 异常的数据丢失会被自动阻止

### 2. 安全面板监控
按 `Ctrl+Shift+S` 打开MD数据安全中心面板：

#### 状态监控
- 🟢 绿色：防误写机制正常运行
- 🔴 红色：防误写机制异常

#### 操作日志
- 查看最近的删除操作记录
- 绿色：合法操作
- 红色：可疑操作

#### 隔离区域
- 显示被保护的异常数据
- 提供清理和强制同步选项

### 3. 手动操作
```javascript
// 手动标记删除操作
window.MDSafeWriter.markDeletion(nodeId, 'ui_delete');

// 获取操作日志
const log = window.MDSafeWriter.getOperationLog();

// 获取隔离数据
const quarantine = window.MDSafeWriter.getQuarantineData();

// 强制写入（跳过安全检查）
await window.MDSafeWriter.forceWrite(projectData);
```

## 📊 工作流程

### 正常删除流程
```
用户按Delete键 → 记录操作(keyboard_delete) → jsMind删除节点 → 
数据保存 → 安全验证通过 → 写入MD底座 ✅
```

### 异常保护流程
```
JavaScript错误 → 节点意外丢失 → 数据保存 → 
安全验证失败 → 阻止MD写入 → 保存到隔离区域 → 通知用户 ⚠️
```

## 🔧 配置选项

### 时间窗口设置
```javascript
// 操作超时时间（默认30秒）
window.MDSafeWriter.operationTimeout = 30000;

// 日志最大条数（默认1000）
window.MDSafeWriter.maxLogSize = 1000;
```

### 删除来源标记
```javascript
const DELETE_SOURCES = {
  KEYBOARD: 'keyboard_delete',      // 键盘删除
  UI_BUTTON: 'ui_delete',          // 界面按钮
  CONTEXT_MENU: 'context_delete',   // 右键菜单
  API_CALL: 'api_delete',          // API调用
  CASCADE: 'cascade_delete',        // 级联删除
  UNKNOWN: 'unknown'               // 未知来源（危险）
};
```

## 🚨 异常处理

### 检测到异常删除时
1. **立即阻止**：停止MD底座写入
2. **数据隔离**：将异常数据保存到隔离区域
3. **用户通知**：显示警告信息
4. **日志记录**：记录详细的异常信息

### 恢复方法
1. **查看隔离区域**：打开安全面板查看被保护的数据
2. **分析原因**：查看操作日志了解异常原因
3. **手动处理**：
   - 清理隔离区域（删除异常数据）
   - 强制同步（接受异常数据）
   - 等待正常操作（让系统自动恢复）

## 📈 性能影响

### 内存使用
- 操作日志：每条约100字节，默认最多1000条
- 隔离数据：按需存储，可手动清理
- 总体影响：< 1MB

### 性能开销
- 删除操作拦截：< 1ms
- 数据验证：< 10ms
- 写入决策：< 1ms
- 总体影响：可忽略不计

## 🛠️ 故障排除

### 常见问题

#### 1. 正常删除被阻止
**原因**：操作记录丢失或时间窗口过期
**解决**：
- 检查操作超时设置
- 查看操作日志确认记录
- 使用强制同步（谨慎）

#### 2. 异常数据未被拦截
**原因**：删除操作被误标记为合法
**解决**：
- 检查删除操作拦截是否正常工作
- 查看操作日志确认来源标记
- 更新jsMind拦截逻辑

#### 3. 隔离区域数据过多
**原因**：频繁的异常检测
**解决**：
- 分析隔离数据找出异常原因
- 修复导致异常的根本问题
- 定期清理隔离区域
