# 脑图三重存储机制详解

## 📋 概述

当前脑图系统采用**三重存储机制**，确保数据的高可用性、高性能和高可靠性。三个存储层分别承担不同的职责，形成完整的数据保障体系。

## 🏗️ 三重存储架构

```
┌─────────────────┐    ┌─────────────────┐    ┌─────────────────┐
│   LocalStorage  │    │   IndexedDB     │    │   MD底座        │
│   (主存储)      │    │   (镜像存储)    │    │   (文档存储)    │
├─────────────────┤    ├─────────────────┤    ├─────────────────┤
│ • 快速读写      │    │ • 版本历史      │    │ • 人类可读      │
│ • 主要数据源    │    │ • 内容哈希      │    │ • 跨平台同步    │
│ • 即时访问      │    │ • 节点索引      │    │ • 备份恢复      │
│ • 5MB限制       │    │ • 无限容量      │    │ • 版本控制      │
└─────────────────┘    └─────────────────┘    └─────────────────┘
         │                       │                       │
         └───────────────────────┼───────────────────────┘
                                 │
                    ┌─────────────────┐
                    │  统一存储API    │
                    │ MindmapStorage  │
                    └─────────────────┘
```

## 💾 第一层：LocalStorage (主存储)

### 存储机制
```javascript
// 主要键值
const KEY = 'mindmap_data_v1';           // 主存储键
const BACKUP_KEY = 'mindmap_data_backup_v1';  // 备份键  
const FULL_KEY = '__mind_full_cache_v1';      // 全图快照键

// 保存流程
function save(payload) {
  const text = JSON.stringify(payload);
  
  // 1. 主写入
  localStorage.setItem(KEY, text);
  
  // 2. 备份写入（降低单键损坏风险）
  localStorage.setItem(BACKUP_KEY, text);
  
  // 3. 全图快照（供快速恢复）
  const snapshot = { meta: payload.meta, format: 'node_tree', data: payload.data };
  localStorage.setItem(FULL_KEY, JSON.stringify(snapshot));
}
```

### 数据格式
```json
{
  "format": "node_tree",
  "data": {
    "id": "root-xxx",
    "topic": "项目名称", 
    "children": [...]
  },
  "meta": {
    "mind_id": "project_001",
    "createdAt": 1726646400000,
    "accessCount": 15
  }
}
```

### 特点与职责
- ✅ **主要数据源**：所有读取操作优先从此获取
- ✅ **即时访问**：同步读写，无延迟
- ✅ **三重备份**：主键+备份键+快照键
- ✅ **容错恢复**：按优先级读取 `KEY → BACKUP_KEY → FULL_KEY`
- ⚠️ **容量限制**：通常5-10MB限制
- ⚠️ **易失性**：清除浏览器数据会丢失

## 🗄️ 第二层：IndexedDB (镜像存储)

### 存储机制
```javascript
// 数据库结构
const DB_NAME = 'MindmapDB';
const STORE_NODES = 'nodes';       // 节点索引表
const STORE_CONTENTS = 'contents'; // 内容哈希表  
const STORE_VERSIONS = 'versions'; // 版本历史表

// 镜像流程 (异步，不阻塞主流程)
async function mirrorToIndexedDB(payload) {
  const nodes = walkNodes(payload.data, []); // 遍历所有节点
  
  for (const node of nodes) {
    const content = node.data?.content || '';
    const hash = await sha256Hex(content);
    
    // 1. 内容去重存储
    contents.put({ 
      content_hash: hash, 
      content, 
      length: content.length,
      updatedAt: now 
    });
    
    // 2. 节点轻量索引
    nodes.put({ 
      node_id: node.id, 
      label: node.topic,
      content_hash: hash,
      updatedAt: now 
    });
    
    // 3. 版本历史记录
    versions.add({ 
      node_id: node.id, 
      content_hash: hash,
      updatedAt: now 
    });
  }
}
```

### 数据结构
```javascript
// nodes表：节点索引
{
  node_id: "node-001",        // 主键
  label: "节点标题",
  content_hash: "sha256...",  // 内容哈希
  updatedAt: "2025-09-18T..."
}

// contents表：内容存储
{
  content_hash: "sha256...",  // 主键
  content: "节点详细内容",
  length: 1024,
  updatedAt: "2025-09-18T..."
}

// versions表：版本历史
{
  id: 1,                      // 自增主键
  node_id: "node-001",        // 外键
  content_hash: "sha256...",  // 外键
  updatedAt: "2025-09-18T..."
}
```

### 特点与职责
- ✅ **版本历史**：完整记录每个节点的修改历史
- ✅ **内容去重**：相同内容只存储一份，节省空间
- ✅ **无限容量**：不受LocalStorage容量限制
- ✅ **结构化查询**：支持按节点ID、内容哈希等查询
- ✅ **异步镜像**：不阻塞主存储流程
- 🔸 **辅助角色**：主要用于历史查询和数据分析
- 🔸 **延迟写入**：异步执行，可能有短暂延迟

## 📝 第三层：MD底座 (文档存储)

### 存储机制
```javascript
// 自动写入流程 (在 mindmapStorage.js 的 save() 中触发)
try {
  if (window.MDBaseManager && payload.meta && payload.meta.mind_id) {
    const projectData = {
      id: payload.meta.mind_id,
      name: payload.data?.topic || '未命名项目',
      payload: payload,
      createdAt: payload.meta.createdAt || Date.now(),
      updatedAt: Date.now(),
      accessCount: (payload.meta.accessCount || 0) + 1
    };
    
    // 异步写入MD底座
    window.MDBaseManager.writeMindmapToMD(projectData);
  }
} catch(_) { 
  // MD底座写入失败不影响主流程
}
```

### 数据格式 (Markdown)
```markdown
## 项目: 脑图的优化和改造 (ID: mind_20250918_001)
- 创建时间: 2025-09-18T02:00:00.000Z
- 最后修改: 2025-09-18T02:15:00.000Z
- 数据温度: hot
- 访问次数: 45

### 脑图结构
```json
{
  "format": "node_tree",
  "data": { ... },
  "meta": { ... }
}
```

### 节点内容
- **根节点** (ID: root-xxx)
  - **子节点1** (ID: child-xxx)
    - 内容: 具体内容文本

```

### 特点与职责
- ✅ **人类可读**：纯文本格式，便于查看和编辑
- ✅ **版本控制**：支持Git等版本控制系统
- ✅ **跨平台同步**：标准Markdown格式通用性强
- ✅ **备份恢复**：可作为完整的数据备份
- ✅ **数据分层**：自动评估数据温度(hot/warm/cold/archive)
- ✅ **服务器同步**：支持与服务器MD文档双向同步
- 🔸 **异步写入**：不阻塞主流程，失败不影响正常使用

## 🔄 三层存储的相互关系

### 写入流程 (数据保存时)
```
用户保存脑图
      ↓
┌─────────────────┐
│ 1. LocalStorage │ ← 主写入 (同步，必须成功)
│   主键+备份键   │
└─────────────────┘
      ↓
┌─────────────────┐
│ 2. IndexedDB    │ ← 镜像写入 (异步，允许失败)
│   节点+内容+版本│
└─────────────────┘
      ↓
┌─────────────────┐
│ 3. MD底座       │ ← 文档写入 (异步，允许失败)
│   项目段落      │
└─────────────────┘
```

### 读取流程 (数据加载时)
```
用户请求数据
      ↓
┌─────────────────┐
│ 1. LocalStorage │ ← 优先读取 (最快)
│ KEY→BACKUP→FULL │
└─────────────────┘
      ↓ (如果失败)
┌─────────────────┐
│ 2. MD底座       │ ← 备用读取 (兼容性)
│ 解析MD恢复JSON  │
└─────────────────┘
      ↓ (如果失败)  
┌─────────────────┐
│ 3. IndexedDB    │ ← 最后手段 (重建)
│ 从历史重建数据  │
└─────────────────┘
```

### 同步关系
```
┌─────────────────┐    写入触发    ┌─────────────────┐
│   LocalStorage  │ ──────────→   │   IndexedDB     │
│     (主)        │               │    (镜像)       │
└─────────────────┘               └─────────────────┘
         │                                 │
         │ 写入触发                        │ 查询支持
         ↓                                 ↓
┌─────────────────┐    服务器同步   ┌─────────────────┐
│    MD底座       │ ←──────────→   │   服务器MD      │
│   (文档)        │               │   (远程)        │
└─────────────────┘               └─────────────────┘
```

## 🛡️ 数据安全策略

### 多重备份保障
1. **LocalStorage三重备份**：主键+备份键+快照键
2. **IndexedDB版本历史**：每次修改都保留历史记录
3. **MD底座文档备份**：人类可读的完整备份
4. **服务器远程备份**：MD文档可同步到服务器

### 故障恢复机制
```javascript
// 读取优先级 (mindmapStorage.js)
function load() {
  // 1. 主键读取
  let obj = localStorage.getItem('mindmap_data_v1');
  if (obj) return JSON.parse(obj);
  
  // 2. 备份键读取  
  obj = localStorage.getItem('mindmap_data_backup_v1');
  if (obj) return JSON.parse(obj);
  
  // 3. 快照键读取
  obj = localStorage.getItem('__mind_full_cache_v1');
  if (obj) return JSON.parse(obj);
  
  // 4. MD底座恢复
  if (window.MDBaseManager) {
    const mdProject = await MDBaseManager.restoreMindmapFromMD(projectId);
    if (mdProject) return mdProject.payload;
  }
  
  // 5. IndexedDB重建 (最后手段)
  return await rebuildFromIndexedDB();
}
```

## 🚀 总结

三重存储机制形成了完整的数据保障体系：

1. **LocalStorage**：承担主要的读写任务，保证性能和响应速度
2. **IndexedDB**：提供版本历史和结构化查询，支持数据分析
3. **MD底座**：确保数据的可读性和跨平台兼容性，支持备份同步

这种架构的核心优势：
- 🔒 **数据安全**：多重备份，故障自动恢复
- ⚡ **高性能**：主存储优化，异步镜像不阻塞
- 🔄 **高可用**：任一层故障都不影响系统运行  
- 📈 **可扩展**：支持大数据分析和AI应用集成
- 🌐 **跨平台**：标准格式便于数据迁移和共享

通过这种设计，你的脑图系统既保持了高性能的用户体验，又获得了企业级的数据可靠性！
