# 脑图数据持久化架构问题与解决方案

**创建时间**: 2025-10-07  
**问题描述**: 脑图节点内容在关机后丢失，刷新页面正常  
**根本原因**: 数据持久化架构存在缺陷

---

## 🔍 问题诊断

### 症状
- ✅ 刷新页面：数据正常（内存缓存有效）
- ❌ 关机重启：数据丢失（持久化失败）
- ⚠️ 节点content字段未被持久化到IndexedDB/LocalStorage

### 表面原因
1. DataCompressor压缩时可能丢失content字段
2. 保存时机不确定（防抖、异步）
3. 浏览器关闭时中断了未完成的写入操作

---

## 🏗️ 架构层面的根本问题

### 问题1：数据流混乱

**当前数据流**:
```
jsMind实例 (内存)
    ↓ get_data()
导出数据 (临时)
    ↓ syncNodeData() [手动同步]
完整数据 (临时)
    ↓ MindmapStorage.saveMindmapData()
    ↓ DataCompressor.compress() [可能丢失数据]
压缩数据 (临时)
    ↓ StorageAdapter.saveMindmap()
    ↓ AutogenUnifiedStorage.store()
    ↓ persistToStorage() [异步]
    ├─→ LocalStorage [同步，可能失败]
    └─→ IndexedDB [异步，可能未完成]
```

**问题点**:
1. **数据同步点过多** - 每个环节都可能丢失数据
2. **异步操作未等待** - 关机时可能中断
3. **无事务保证** - 部分成功部分失败
4. **无一致性验证** - 不知道是否真正保存成功

### 问题2：缺乏统一的数据生命周期管理

**应该有的架构**:
```
[数据源] → [验证] → [转换] → [持久化] → [验证] → [确认]
```

**当前架构**:
```
[数据源] → [多次转换] → [异步保存] → ❌ 无验证
```

### 问题3：违反架构原则

根据`审查员：项目管理应用架构功能清单.md`，应该：
- ✅ 使用AutogenUnifiedStorage统一存储
- ✅ 使用MD底座数据结构
- ❌ **缺失**: 数据一致性保证
- ❌ **缺失**: 持久化事务机制
- ❌ **缺失**: 数据恢复策略

---

## 🎯 正确的架构设计

### 架构原则

1. **单一数据源原则** (Single Source of Truth)
   - jsMind实例是唯一的运行时数据源
   - 持久化数据是唯一的持久数据源
   - 两者必须保持同步

2. **事务性保存原则** (Transactional Save)
   - 要么全部成功，要么全部失败
   - 保存前验证，保存后验证
   - 失败时自动回滚或重试

3. **分层持久化原则** (Layered Persistence)
   - L1: 内存缓存（快速访问）
   - L2: LocalStorage（同步持久化）
   - L3: IndexedDB（大容量持久化）
   - L4: JSON底座（服务器同步）

4. **数据一致性原则** (Data Consistency)
   - 保存时计算哈希值
   - 读取时验证哈希值
   - 不一致时触发恢复流程

### 新架构设计

```
┌─────────────────────────────────────────────────────────┐
│                    脑图数据持久化架构                      │
└─────────────────────────────────────────────────────────┘

┌─────────────────┐
│  jsMind实例     │ ← 唯一运行时数据源
│  (内存数据)     │
└────────┬────────┘
         │
         ↓ 触发保存事件
┌─────────────────────────────────────────────────────────┐
│              PersistenceManager (新组件)                 │
│  职责：统一管理数据持久化生命周期                          │
├─────────────────────────────────────────────────────────┤
│  1. 数据采集层 (Data Collection)                         │
│     - 从jsMind获取完整数据                                │
│     - 同步所有节点的content                               │
│     - 验证数据完整性                                      │
│                                                          │
│  2. 数据转换层 (Data Transformation)                     │
│     - 转换为MD底座格式                                    │
│     - 智能压缩（保留content）                             │
│     - 计算数据哈希值                                      │
│                                                          │
│  3. 事务保存层 (Transactional Save)                      │
│     - 开始事务                                           │
│     - 同步保存到LocalStorage                             │
│     - 异步保存到IndexedDB (await)                        │
│     - 验证保存结果                                       │
│     - 提交或回滚                                         │
│                                                          │
│  4. 验证确认层 (Verification)                            │
│     - 清除内存缓存                                       │
│     - 从持久层读取                                       │
│     - 验证哈希值                                         │
│     - 确认数据一致性                                     │
└─────────────────────────────────────────────────────────┘
         │
         ↓ 持久化完成
┌─────────────────────────────────────────────────────────┐
│              AutogenUnifiedStorage                       │
│  L1: 内存缓存 (Map)                                      │
│  L2: LocalStorage (同步)                                 │
│  L3: IndexedDB (异步，必须await)                         │
└─────────────────────────────────────────────────────────┘
```

## 💡 解决方案

### 方案1：创建PersistenceManager组件

**文件**: `src/core/storage/PersistenceManager.js`

**职责**:
1. 统一管理数据持久化生命周期
2. 提供事务性保存机制
3. 数据一致性验证
4. 自动恢复策略

**核心API**:
```javascript
class PersistenceManager {
    // 事务性保存
    async saveWithTransaction(dataSource, options)
    
    // 验证持久化
    async verifyPersistence(key)
    
    // 恢复数据
    async recoverData(key)
    
    // 健康检查
    async healthCheck()
}
```

### 方案2：增强AutogenUnifiedStorage

**改进点**:
1. `persistToStorage()` 必须等待IndexedDB完成
2. 添加保存前/后钩子
3. 添加数据哈希验证
4. 添加保存失败重试机制

### 方案3：修复MindmapStorage

**改进点**:
1. 移除防抖机制（或提供立即保存选项）
2. 保存前强制同步所有节点content
3. 保存后验证数据完整性
4. 提供保存状态回调

### 方案4：添加beforeunload保护

**改进点**:
1. 监听`beforeunload`事件
2. 强制同步保存所有数据
3. 等待持久化完成
4. 必要时阻止页面关闭

## 🔧 立即行动项

### 1. 修复AutogenUnifiedStorage.persistToStorage()

**问题**: 异步保存未等待完成

**修复**:
```javascript
async persistToStorage(key, item) {
    // 同步保存到LocalStorage
    const lsSuccess = this.setToLocalStorage(key, item);
    
    // 异步保存到IndexedDB - 必须等待
    const idbSuccess = await this.setToIndexedDB(key, item);
    
    // 验证保存结果
    if (!lsSuccess && !idbSuccess) {
        throw new Error('持久化完全失败');
    }
    
    return { lsSuccess, idbSuccess };
}
```

### 2. 添加beforeunload强制保存

**位置**: `mindmap-standalone.html`

**实现**:
```javascript
window.addEventListener('beforeunload', async (e) => {
    // 获取当前数据
    const data = this.jm.get_data();
    
    // 同步所有节点content
    syncNodeData(data.data);
    
    // 强制同步保存
    try {
        await this.saveToUnifiedStorage(data);
        
        // 等待持久化完成
        await new Promise(resolve => setTimeout(resolve, 100));
    } catch (error) {
        // 保存失败，阻止关闭
        e.preventDefault();
        e.returnValue = '数据尚未保存完成，确定要离开吗？';
        return e.returnValue;
    }
});
```

### 3. 添加保存验证机制

**实现**:
```javascript
async saveAndVerify(data) {
    // 1. 保存
    const success = await this.saveToUnifiedStorage(data);
    
    if (!success) {
        throw new Error('保存失败');
    }
    
    // 2. 验证
    const retrieved = await AutogenUnifiedStorage.retrieve('mindmap', 'current');
    
    if (!retrieved) {
        throw new Error('验证失败：无法读取保存的数据');
    }
    
    // 3. 对比哈希
    const savedHash = this.calculateHash(data);
    const retrievedHash = this.calculateHash(retrieved);
    
    if (savedHash !== retrievedHash) {
        throw new Error('验证失败：数据不一致');
    }
    
    return true;
}
```
