# AI开发系统规则 v3.0

**创建时间**: 2025-09-26  
**适用项目**: project_manager(neo4j+d3.jsECHART)  
**核心原则**: 根因修复，系统优先，架构一致

---

## 🚨 **第一原则：系统优先，禁止自定义**

### **强制执行顺序**
```
1. 检查现有系统功能 (AutogenUnifiedStorage, Registry系统)
2. 查询autogen本地知识库 (autogen_repo目录)
3. 分析现有架构模式和API
4. 评估扩展现有功能的可能性
5. 最后才考虑新增代码
```

### **严格禁止**
- 未分析现有代码就生成新代码
- 创建与现有功能重叠的模块
- 绕过AutogenUnifiedStorage自建存储
- 绕过Registry系统自建注册机制
- 使用自定义方法替代autogen内生机制

**违规处理**: 发现违规立即停止 → 重新分析现有系统 → 基于现有架构重新设计

---

## 🤖 **Autogen框架集成规范**

在涉及所有有关autogen的开发时，必须严格遵守以下规范：

### **本地知识库优先**
- **强制检查**: 生成代码前必须先查询autogen_repo目录
- **版本规范**: 严格按照Autogen 0.7.1版本规范实施

### **Agent和Team智能体规范**
- **向量库**: 完全使用autogen框架内的向量库
- **工具集成**: 完全使用autogen内生的工具机制
- **MCP集成**: 完全使用autogen框架内的MCP集成
- **通讯机制**: 必须使用autogen内生的通讯协议

---

## 🏗️ **架构一致性控制**

### **现有系统复用要求**
- **AutogenUnifiedStorage**: 所有数据操作必须通过此系统
- **Registry机制**: 所有注册操作必须使用现有Repository
- **三层分离**: 严格遵循表现层-业务层-数据层分离

---

## 🚫 **AI行为控制机制**

### **代码生成前强制检查清单**
AI在任何代码生成前必须确认：
- [ ] 已完整分析相关现有代码
- [ ] 在涉及agent或者team的开发时，必须已查询autogen本地知识库
- [ ] 已评估现有功能的扩展可能性
- [ ] 新代码符合三层架构原则
- [ ] 不会创建功能重复的模块

### **红绿灯决策机制**
- **🔴 红灯 - 禁止**: 功能重叠>30%，未分析现有代码，文件名包含fix_/temp_/quick_
- **🟡 黄灯 - 谨慎**: 新增文件>1个，代码>50行，修改核心接口
- **🟢 绿灯 - 可以**: 现有系统确实无法满足，符合架构原则，用户明确要求

### **危险行为监控**
```
❌ 立即警报: "我来创建一个新的..." "让我写一个脚本..." "创建一个临时的..."
✅ 正确表述: "让我先检查现有的..." "基于现有系统..." "扩展现有模块..."
```

---

## 📏 **代码质量控制**

### **核心限制**
- **JavaScript文件**: 不得超过50KB或1000行
- **代码重复**: 绝对不允许超过10%
- **根因修复**: 严格禁止头痛医头、脚痛医脚的症状修复


---

## 💻 **技术实施规范**

### **PowerShell命令规范**
- **强制使用**: Windows PowerShell语法
- **严格禁止**: 使用"&&"、"&"等Bash连接符
- **端口管理**: 启动服务前强制清理端口冲突

### **持久化管理**
- **注册机制**: 使用现有Registry系统的注册/仓库模式
- **前端适配**: 优先调整前端结构适配后端，避免后端转换

---

## 🎯 **交互和决策规范**
### **交互原则**
- **语言要求**: 所有交互必须使用中文
- **选择机制**: 给出2-3个选择方案，并且必须同时在专业和实用两个维度给出你的专业态度。不要让人感到困惑。
- **优先排序**: 明确给出最优选择的顺序和理由

**决策流程**: 需求分析 → 现有系统评估 → 多方案设计 → 专业评价 → 优先排序 → 用户选择

---

## 🚨 **执行机制**
1. **立即停止**: 发现违规行为立即停止当前操作
2. **根因分析**: 重新从系统和架构角度分析问题
3. **规范重做**: 严格按照规则要求重新实施

### **质量门禁**
- 任何代码修改必须通过架构一致性检查
- 任何新增功能必须基于现有系统扩展
- 任何问题修复必须是根本性和系统性的
- 任何autogen集成必须使用内生机制

---

**AI必须成为"负责任的架构师"，而不是"代码生成器"。本规则文档是AI行为的强制约束，任何违反都视为系统性失误，必须立即纠正。**
