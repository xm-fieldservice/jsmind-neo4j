## 🎯 核心概念

### 基本原理

通过**复制节点及其所有子节点**的方法，来建立并表述节点之间的逻辑关系。复制操作本身即表示关联关系的建立。

**核心思想**: 用拖拽复制、单纯复制的方法表达手动建立关系。直接拷贝表示有关联。

### 虚拟节点（关系节点）

- **定义**: 通过复制创建的节点称为"虚拟节点"或"关系节点"
- **特征**: 
  - 在 `data.source_node_id` 中保存原始节点ID
  - 使用特殊颜色标识（浅灰色或其他浅色底色，区别于白色底色）
  - 标题前添加关系符号标识
  - 所有子节点同样改变颜色并保存源节点ID
  - **强关系**的节点字体颜色设置为蓝色

### 源节点计数器

- **功能**: 在源节点标题后显示被复制次数
- **格式**: `[复制×N]`
- **存储**: `data.copy_count` 和 `data.original_topic`
- **含义**: 记录的是复制次数，也就是建立直接关系的次数

## 🔗 关系类型定义

### 与Neo4j对齐的三种关系

| 关系类型 | 说明 | Neo4j对应 |
|---------|------|-----------|
| **关联关系** | 两个节点有说不清的双向关联 | 无向关系 |
| **出向关系** | 影响力的推及，表示新的源节点对于复制过来的节点有影响力 | 出向边 (OUTGOING) |
| **入向关系** | 因果逻辑关系；新的源节点是复制过来的节点的'果'，也就是说，没有复制过来的节点，就没有新的源节点 | 入向边 (INCOMING) |

### 六种关系强度

#### 出向关系（影响力）

| 符号 | Unicode | 强度 | 含义 | 字体颜色 |
|-----|---------|------|------|----------|
| ⮕ | `\u2B95` | 普通 | 影响力 | 黑色 `#000000` |
| ⮕⮕ | `\u2B95\u2B95` | 强 | 强影响力 | **蓝色 `#0066cc`** |

#### 入向关系（因果逻辑）

| 符号 | Unicode | 强度 | 含义 | 字体颜色 |
|-----|---------|------|------|----------|
| 🔙 | `\U0001F519` | 普通 | 逻辑决定 | 黑色 `#000000` |
| 🔙🔙 | `\U0001F519\U0001F519` | 强 | 强逻辑决定 | **蓝色 `#0066cc`** |

#### 关联关系（双向）

| 符号 | Unicode | 强度 | 含义 | 字体颜色 |
|-----|---------|------|------|----------|
| ⬌ | `\u2B0C` | 普通 | 单纯关联 | 黑色 `#000000` |
| ⇔ | `\u21D4` | 强 | 强关联 | **蓝色 `#0066cc`** |

## 🎨 颜色规范

### 节点颜色体系

| 节点类型 | 背景色 | 字体颜色 | 说明 |
|---------|--------|---------|------|
| **默认节点** | `#ffffff` 白色 | `#000000` 黑色 | 所有普通节点默认白色背景 |
| **关系节点（普通）** | `#f5f5f5` 浅灰色 | `#000000` 黑色 | 虚拟节点，区别于白色 |
| **关系节点（强）** | `#f5f5f5` 浅灰色 | `#0066cc` 蓝色 | 强关系节点，蓝色字体突出 |

### 颜色选择理由

```yaml
背景色 #f5f5f5 (浅灰色):
  - 与白色 #ffffff 有明显区别
  - 不会过于突兀，保持视觉和谐
  - 适合长时间查看，不刺眼

字体色 #0066cc (蓝色):
  - 表示强关系的重要性
  - 与黑色形成对比，易于识别
  - 符合常见UI设计规范（蓝色=链接/关联）
```

## 🛠️ 实现方法

### 方法1: 拖拽复制（默认关联关系）

**操作**: 鼠标右键拖拽节点到新父节点

**行为**:
- 复制节点及所有子节点到新位置
- 自动添加 `⬌` 符号到标题最前面
- 设置虚拟节点背景色为 `#f5f5f5`（浅灰色）
- 所有子节点同样改变颜色并保存源节点ID
- 源节点计数器 +1

**关系类型**: 默认为"单纯关联 ⬌"

**限制**: 无法定义出向和入向关系，只能定义"复制⬌向关系"

---

### 方法2: 快捷键复制（默认关联关系）

**操作**: 
1. 选中节点，按 `Ctrl+C` 复制
2. 选中目标父节点，按 `Ctrl+V` 粘贴

**行为**:
- 复制节点及所有子节点到新位置
- 自动添加 `⬌` 符号到标题最前面
- 设置虚拟节点背景色为 `#f5f5f5`（浅灰色）
- 字体颜色保持黑色 `#000000`（普通关系）
- 所有子节点同样改变颜色并保存源节点ID
- 源节点计数器 +1

**关系类型**: 默认为"单纯关联 ⬌"

**限制**: 无法定义出向和入向关系，只能定义"复制⬌向关系"

---

### 方法3: 右键菜单（指定关系类型）

**操作**: 右键点击节点 → "关系管理" → 选择关系类型

**二级菜单项**:

```
📋 关系管理
  ├─ ⮕ 复制节点（影响力）
  ├─ ⮕⮕ 复制节点（强影响力）
  ├─ 🔙 复制节点（逻辑决定）
  ├─ 🔙🔙 复制节点（强逻辑决定）
  ├─ ⬌ 复制节点（单纯关联）
  └─ ⇔ 复制节点（强关联）
```

**行为**:
1. 点击菜单项后，节点进入"待粘贴"状态
2. 选中目标父节点，右键选择"粘贴关系节点"
3. 根据选择的关系类型，在标题前添加对应符号
4. 设置虚拟节点背景色为 `#f5f5f5`（浅灰色）
5. 如果是**强关系**（⮕⮕/🔙🔙/⇔），字体颜色设置为蓝色 `#0066cc`
6. 如果是**普通关系**（⮕/🔙/⬌），字体颜色保持黑色 `#000000`
7. 所有子节点同样改变颜色并保存源节点ID
8. 源节点计数器 +1

**优势**: 可以精确定义出向、入向和关联关系

### 2. 关系类型枚举

```javascript
const RelationType = {
    OUTGOING: 'outgoing',           // 出向关系
    INCOMING: 'incoming',           // 入向关系
    BIDIRECTIONAL: 'bidirectional'  // 关联关系
};

const RelationStrength = {
    NORMAL: 'normal',  // 普通强度
    STRONG: 'strong'   // 强关系
};

const RelationSymbols = {
    'outgoing_normal': '⮕',
    'outgoing_strong': '⮕⮕',
    'incoming_normal': '🔙',
    'incoming_strong': '🔙🔙',
    'bidirectional_normal': '⬌',
    'bidirectional_strong': '⇔'
};

// 颜色配置
const RelationColors = {
    BACKGROUND: '#f5f5f5',        // 浅灰色背景（所有关系节点）
    NORMAL_TEXT: '#000000',       // 黑色字体（普通关系）
    STRONG_TEXT: '#0066cc',       // 蓝色字体（强关系）
    DEFAULT_NODE: '#ffffff'       // 白色背景（默认节点）
};
```

### 3. 核心函数

#### 复制节点函数

```javascript
function copyNodeWithRelation(sourceNodeId, targetParentId, relationType, relationStrength) {
    const sourceNode = jm.get_node(sourceNodeId);
    const newNodeId = jsMind.util.uuid.newid();
    
    // 1. 准备复制数据
    const copiedData = Object.assign({}, sourceNode.data);
    copiedData.source_node_id = sourceNode.id;
    copiedData.relation_type = relationType;
    copiedData.relation_strength = relationStrength;
    copiedData['background-color'] = RelationColors.BACKGROUND;  // 浅灰色背景
    copiedData['foreground-color'] = relationStrength === 'strong' 
        ? RelationColors.STRONG_TEXT   // 强关系用蓝色
        : RelationColors.NORMAL_TEXT;  // 普通关系用黑色
    
    // 2. 生成关系符号
    const symbol = RelationSymbols[`${relationType}_${relationStrength}`];
    const newTopic = `${symbol} ${sourceNode.topic}`;
    
    // 3. 创建虚拟节点
    const newNode = jm.add_node(targetParentId, newNodeId, newTopic, copiedData);
    
    // 4. 递归复制所有子节点
    if (sourceNode.children && sourceNode.children.length > 0) {
        copyChildrenRecursively(sourceNode, newNode, relationType, relationStrength);
    }
    
    // 5. 更新源节点计数器
    updateSourceNodeCounter(sourceNode, newNodeId, relationType, relationStrength);
    
    return newNode;
}
```

#### 递归复制子节点

```javascript
function copyChildrenRecursively(sourceNode, targetNode, relationType, relationStrength) {
    sourceNode.children.forEach(child => {
        const childId = jsMind.util.uuid.newid();
        const childData = Object.assign({}, child.data);
        childData.source_node_id = child.id;
        childData.relation_type = relationType;
        childData.relation_strength = relationStrength;
        childData['background-color'] = RelationColors.BACKGROUND;  // 浅灰色背景
        childData['foreground-color'] = relationStrength === 'strong'
            ? RelationColors.STRONG_TEXT   // 强关系用蓝色
            : RelationColors.NORMAL_TEXT;  // 普通关系用黑色
        
        const newChild = jm.add_node(targetNode, childId, child.topic, childData);
        
        if (child.children && child.children.length > 0) {
            copyChildrenRecursively(child, newChild, relationType, relationStrength);
        }
    });
}
```

#### 更新源节点计数器

```javascript
function updateSourceNodeCounter(sourceNode, copiedNodeId, relationType, relationStrength) {
    // 初始化计数器
    if (!sourceNode.data.copy_count) {
        sourceNode.data.copy_count = 0;
        sourceNode.data.original_topic = sourceNode.topic;
        sourceNode.data.copied_to = [];
    }
    
    // 增加计数
    sourceNode.data.copy_count++;
    
    // 记录复制信息
    sourceNode.data.copied_to.push({
        node_id: copiedNodeId,
        relation_type: relationType,
        relation_strength: relationStrength,
        timestamp: new Date().toISOString()
    });
    
    // 更新标题显示
    const baseTopic = sourceNode.data.original_topic;
    const newTopic = `${baseTopic} [复制×${sourceNode.data.copy_count}]`;
    jm.update_node(sourceNode.id, newTopic);
}
```

## 📊 数据导出与Neo4j集成

### 导出关系数据

```javascript
function exportRelationsToNeo4j() {
    const relations = [];
    
    // 遍历所有节点，提取关系信息
    jm.get_data().data.forEach(node => {
        if (node.data && node.data.source_node_id) {
            relations.push({
                source: node.data.source_node_id,
                target: node.id,
                type: node.data.relation_type,
                strength: node.data.relation_strength,
                label: node.topic
            });
        }
    });
    
    return relations;
}
```

### Neo4j Cypher查询示例

```cypher
// 创建节点关系
MATCH (source:Node {id: $sourceId})
MATCH (target:Node {id: $targetId})
CREATE (source)-[r:RELATES_TO {
    type: $relationType,
    strength: $relationStrength,
    created_at: datetime()
}]->(target)
RETURN r
```

## 📝 备注

1. **节点颜色规范**: 
   - 默认节点：白色背景 `#ffffff`
   - 关系节点：浅灰色背景 `#f5f5f5`（区别于白色）
   - 强关系节点：浅灰色背景 + 蓝色字体 `#0066cc`
2. **关系符号位置**: 显示在节点标题最前面
3. **数据持久化**: 所有关系数据存储在节点的 `data` 对象中
4. **Neo4j兼容**: 支持导出为Neo4j兼容格式
5. **计数器保留**: 计数器信息会在导出/导入时保留
6. **子节点处理**: 虚拟节点的所有子节点都要保存原来节点的ID并继承相同颜色
