## 🔍 根本原因

### 问题分析

**JSON.stringify() 无法序列化jsMind节点对象**

jsMind的节点对象包含：
- 父节点引用 (`parent`)
- 子节点引用 (`children`)
- jsMind实例引用
- 其他内部属性

这些形成了**循环引用**，导致 `JSON.stringify()` 失败并返回空对象 `{}`。

### 错误的实现

```javascript
// ❌ 错误：JSON.stringify无法处理循环引用
cloneNode(node) {
    try {
        const cloned = JSON.parse(JSON.stringify(node));
        console.log('[节点剪贴板] 节点克隆成功');
        return cloned;
    } catch (err) {
        console.error('[节点剪贴板] 节点克隆失败:', err);
        return null;  // 返回null，导致剪贴板为空
    }
}
```

---

## ✅ 修复方案

### 正确的实现

**手动提取需要的数据，避免循环引用**

```javascript
// ✅ 正确：手动提取节点数据
cloneNode(node) {
    try {
        // 手动提取节点数据，避免循环引用
        const cloned = {
            id: node.id,
            topic: node.topic,
            data: node.data ? JSON.parse(JSON.stringify(node.data)) : {},
            children: []
        };
        
        // 递归克隆子节点
        if (node.children && node.children.length > 0) {
            cloned.children = node.children.map(child => this.cloneNode(child));
        }
        
        console.log('[节点剪贴板] 节点克隆成功:', cloned.topic);
        return cloned;
    } catch (err) {
        console.error('[节点剪贴板] 节点克隆失败:', err);
        return null;
    }
}
```

### 修复要点

1. **只提取需要的属性**
   - `id` - 节点ID
   - `topic` - 节点标题
   - `data` - 节点数据（内容、属性等）
   - `children` - 子节点数组

2. **递归处理子节点**
   - 使用 `map()` 递归克隆每个子节点
   - 避免直接引用原节点对象

3. **安全的数据克隆**
   - `node.data` 使用 `JSON.parse(JSON.stringify())` 深拷贝
   - 因为 `data` 是纯数据对象，不包含循环引用

## 🎯 技术细节

### jsMind节点对象结构

```javascript
// jsMind节点对象（包含循环引用）
{
    id: "node_123",
    topic: "节点标题",
    data: { content: "..." },
    parent: { ... },        // 循环引用
    children: [ ... ],      // 包含父节点引用
    _data: { ... },         // 内部数据
    isroot: false,
    direction: "right"
}
```

### 我们需要的数据结构

```javascript
// 纯数据结构（无循环引用）
{
    id: "node_123",
    topic: "节点标题",
    data: { content: "..." },
    children: [
        {
            id: "node_124",
            topic: "子节点",
            data: { ... },
            children: []
        }
    ]
}
```

## 📝 经验教训

### 1. 不能假设对象可以JSON序列化

**教训**: 复杂对象（特别是DOM对象、框架对象）通常包含循环引用

**改进**:
- 使用前测试 `JSON.stringify()`
- 手动提取需要的属性
- 避免序列化整个对象

### 2. 必须测试实际场景

**教训**: 代码写完后必须实际测试，不能只看逻辑

**改进**:
- 每个功能都要实际测试
- 测试边界情况
- 查看控制台日志

### 3. 错误处理要完善

**教训**: `catch` 块返回 `null` 导致后续逻辑失败

**改进**:
- 错误处理要考虑后续影响
- 提供降级方案
- 记录详细的错误信息
