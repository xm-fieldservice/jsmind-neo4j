## 🔍 问题根因

### 统一化重构的副作用
在节点操作统一化重构时，`addNodeTree()`方法改为调用`_createNodeCore()`，导致：

**问题1**: 每个粘贴的子节点都会自动选中和进入编辑模式
- 现象：粘贴带子节点的节点树时，会不断切换选中状态
- 原因：`_createNodeCore()` → `_postProcessNode()` 会对每个节点执行选中和编辑

**问题2**: 递归粘贴时用户体验混乱
- 现象：粘贴10个节点会触发10次选中和编辑
- 原因：统一核心引擎设计为用户主动创建，不适合批量操作

---

## 🛠️ 修复方案

### 设计思路
**保持时间戳统一，但避免过度自动化**

1. ✅ 保留时间戳统一生成（符合统一化原则）
2. ✅ 直接调用jsMind API（避免自动选中）
3. ✅ 只对根节点选中和编辑（改善用户体验）
4. ✅ 递归子节点不触发选中（避免混乱）

### 修复代码

```javascript
addNodeTree(parent, nodeData, isRoot = true) {
    // 生成新的唯一ID
    const newId = this._generateNodeId();
    const timestamp = this.getTimestamp();
    
    // 创建节点（直接使用jsMind API，避免自动选中和编辑）
    const node = this.jm.add_node(parent, newId, nodeData.topic, {
        direction: 'right'
    });
    
    if (node) {
        // ✅ 统一设置时间戳和内容
        if (!node.data) node.data = {};
        node.data.content = timestamp + '\n\n';
        
        // 复制其他节点数据
        if (nodeData.data) {
            Object.assign(node.data, nodeData.data);
        }
        
        // 递归添加子节点
        if (nodeData.children && nodeData.children.length > 0) {
            nodeData.children.forEach(child => {
                this.addNodeTree(node, child, false);  // ⚠️ isRoot=false
            });
        }
        
        // 只有根节点才选中和进入编辑模式
        if (isRoot) {
            this.jm.select_node(newId);
            this.jm.begin_edit(newId);
        }
    }
    
    return node;
}
```

### 关键改进
| 改进点 | 说明 | 效果 |
|--------|------|------|
| **isRoot参数** | 区分根节点和子节点 | 只对根节点执行选中和编辑 |
| **直接调用API** | 绕过统一核心引擎 | 避免自动化副作用 |
| **保留时间戳** | 统一生成时间戳 | 符合统一化原则 |
| **数据复制** | Object.assign保留原数据 | 保持节点完整性 |

## 🎯 统一化原则保持

### ✅ 符合统一化架构

虽然`addNodeTree`不使用`_createNodeCore()`，但仍然符合统一化原则：

1. **时间戳统一** ✅
   - 使用统一的`getTimestamp()`方法
   - 格式完全一致

2. **ID生成统一** ✅

   - 避免ID冲突

3. **数据格式统一** ✅

4. **行为一致** ✅

   - 子节点不干扰（改善用户体验）

## 📊 架构影响分析

### 对统一化架构的影响
| 影响项 | 评估 | 说明 |
|--------|------|------|
| **核心引擎** | 无影响 | `_createNodeCore()`保持不变 |
| **API一致性** | 无影响 | `addChild/addBrother/addCustomNode`不变 |
| **时间戳统一** | 保持 | 继续使用统一方法 |
| **代码重复** | 轻微增加 | `addNodeTree`有独立逻辑，但合理 |

### 合理性论证
`addNodeTree`是**批量操作**，与**单节点创建**场景不同：

| 场景 | 特点 | 适合方案 |
|------|------|----------|
| **单节点创建** | 用户主动，需要立即编辑 | 使用统一核心引擎 |
| **批量粘贴** | 系统操作，需要流畅体验 | 直接API调用 |

**结论**: 这是**合理的架构分层**，不是统一化失败。
